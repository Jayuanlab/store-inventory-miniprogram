# 聚友通信城内部进销存

一个门店、一个店内库存地点。仅供老板、店长、员工、仓管使用，不包含顾客商城、独立维修模块或预警模块。

## 已实现

- 订货、分批收货、实际进价、数量/串码库存；采购默认未付款。
- 供应商双向往来：待付、应退、预付、仅抵货款四类余额，分次/合并付款、退款、抵扣和撤销分配、期初登记、Excel 对账单。
- 采购退货与调价补差先预览再确认；关联串码或可追溯的加权成本来源，区分库存、已售和维修耗材成本，不改原销售及工资快照。
- 搜索商品或串码、多商品开单、实际售价、全额收款、销售人与录单人分开记录。
- 原销售单部分/全部退货退款，关联库存、收支及当月提成回冲。
- 维修作为普通销售：直接销售维修件，或销售服务并登记实际消耗的材料；服务退款不自动退回已消耗材料。
- 号卡顾客价款与运营商佣金分账；预计、确认、分次到账、未到账调整、已到账扣回。
- 老板和所有店长设置商品按件/毛利比例提成、员工底薪及生效月份。
- 销售当月计提、退货当月扣回；保留原规则与成本快照；未设置显示待核算。
- 老板查看全员工资，员工和仓管查看本人；历史月份确认工资及记录实际发放，不自动转账。
- 北京时间日报、收支流水、库存数量盘点、Excel 期初预览与确认导入。
- 库存按现有一级、二级、三级分类联动筛选，按完整分类路径分组；名称、编号、规格、分类或串码直接搜索，切换上级自动清空下级，缺少分类的商品仍可查询。
- 后端身份和权限检查、事务回滚、重复提交保护、网络失败不冒充开单成功。

## 本机启动

需要 Node.js 24，依赖已安装。

```sh
npm run server
```

后端默认在 http://127.0.0.1:3100。打开微信开发者工具中的本项目，点击“编译”，在“本机体验账号”中选择示例老板、示例员工甲、示例员工乙或示例仓管。

这是真实读写本地数据库的开发体验，不是真实微信身份认证。选择账号只在开发模式、无微信密钥且请求来自本机时开放。不要把未完成部署配置的开发服务公开到互联网。

## 使用顺序

1. 老板进入“我的 → 底薪与提成设置”：先填写员工底薪及生效月，再设置各商品提成方式。
2. 员工在“开单”搜索商品，填写实际售价，串码商品选择具体串码，确认收款。
3. 老板在“我的 → 全员工资”选择月份和员工；员工同一入口只能看到本人工资。
4. 月份结束、底薪及待核算提成补齐后，老板确认工资；实际支付后记录已发放。
5. 退货从“销售单据”的原单办理，不能直接改历史销售额或历史工资。
6. 老板从“首页 → 供应商往来”进入档案，核对期初、付款、退款和抵货款；“进退货”办理收货和采购退货，“调价补差”核对成本变化后确认。
7. “库存”可逐级选择分类，也可只选一级或二级查看其下全部商品。搜索在当前分类内进行；“重置分类”保留关键字并扩展到全部库存。商品详情显示完整分类、规格及原有串码、盘点入口，不改变分类数据或库存数量。

供应商功能和当前边界见 [供应商模块使用说明](docs/supplier-current-account-implementation.md)。店长默认可查看往来、登记订货和收货，付款/退款/抵扣/成本调整默认由老板确认；仓管不能读取供应商结款余额。工资规则权限仍保持所有店长可以设置。

按毛利提成当前采用 `max(销售额 - 实际出库成本, 0) × 比例`；亏损销售不会自动产生罚款。运营商预计或到账佣金不会自动进入员工提成，这项经营规则尚未确定。

## 数据与备份

首次启动时，原 `server/data/store.json` 备份至 `server/data/before-erp-upgrade.json`，再迁入 `server/data/store.sqlite`。此后数据写入 SQLite，不再写原 JSON。

升级保留现有账套，不重新导入真实库存、不补造串码、不覆盖用户已填写的工资或单据。测试数据仅写入独立内存数据库；供应商期初需另外核对，不能从库存总价推算。

```sh
npm run backup
```

备份生成在 `server/backups`，使用 SQLite 在线备份并检查完整性。恢复时先停止后台，保留当前数据库及 WAL/SHM 文件的完整副本，确认备份有效后再替换数据库；不要在服务运行时直接覆盖数据库，也不要只拷贝正在写入的主文件。

当前是适合单机验证的 SQLite 事务版，记录按集合存储，尚非规范化关系表的生产 ERP。大规模数据、跨服务器扩展和正式部署前，应进一步拆表、补数据库约束、分页、持久会话及定期备份恢复演练。

## 正式微信登录

- 当前工程 AppID 仍为 `touristappid`，不能代替正式小程序。
- 后端配置放在 `server/.env`，字段见 `server/.env.example`；正式环境需 `NODE_ENV=production`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`。
- 配置真实 AppID、HTTPS 请求域名，并将 `utils/api.js` 的 API 地址改为可访问的正式后端；手机中的 127.0.0.1 不是这台电脑。
- 已实现 `wx.login → code2Session → 员工 openid 匹配`。员工绑定接口为老板专用 `POST /api/users/bind`，需登录令牌和请求编号；首个老板绑定及正式员工绑定流程仍需在部署时配置，尚无自助邀请界面。
- 未绑定、停用或登录失效的账号不会回退成老板。登录会话目前有效 8 小时，后台重启后需重新登录。
- 微信密钥只保留在后端，不能放入小程序或发给员工。

## 验证

```sh
npm run check
npm run server:test
npm run pages:test
npm run inventory:test
npm run suppliers:test
npm run import:test
npm run wechat:check
npm run wechat:qa
npm run suppliers:qa
```

后端与导入测试使用独立内存数据库，不访问日常账套。页面测试覆盖全部页面的断网状态、商品/型号/串码搜索、销售归属和不确定请求重试。

`inventory:test` 验证三级联动、同名分类隔离、缺失层级、重置搜索范围和刷新后保留有效选择。`node scripts/qa-inventory-wechat.js` 在已登录的微信开发者工具中只读验证库存分组、筛选、详情、空结果和搜索，截图输出到系统临时目录 `store-inventory-qa`；不会提交盘点。

`wechat:check` 使用本机微信编译器验证 JS/JSON/WXML/WXSS；`wechat:qa` 需要开发者工具服务端口与 9420 自动化端口，截图保存在系统临时目录 `store-erp-wechat-qa`。自动化只读取业务数据和打开编辑表单，不提交真实工资或销售。

`suppliers:test` 用隔离的 HTTP 服务驱动实际页面方法，覆盖供应商建档到付款、补差、退货及导出；`suppliers:qa` 需先运行它生成验收样本，使用本机工具截图并检查视口宽度。样本余额仅替换页面内存中的渲染数据，不写门店账套，结束后回到真实首页。

Excel 解析使用 SheetJS 官方 0.20.3 发行包，来源见 [官方安装说明](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)。

## 尚未实现

寄售/借机、换机流程、保证金、个人代付独立往来、条件返利核算、供应商与客户跨业务抵账、坏货库存、串码盘点、收银日结核对、考勤及入离职折算、多人分摊提成、运营商佣金参与工资、会计税费与自动支付仍未实现。当前实物销售退货仅适用于可再次销售商品。

供应商调价目前由店内按已达成的协议直接确认，尚无补差申请审批流、附件上传和历史截止日自动资格快照。后续补差不自动补发员工提成；来源缺失、盘点或采购退货打断成本追溯时会拒绝自动分配，不直接改成本凑余额。

主要代码：`server/src/erp.js`（业务）、`payroll.js`（工资）、`application.js`（认证与接口）、`repository.js`（事务）；前端保持原生微信页面，没有失败后回退的模拟业务数据。
