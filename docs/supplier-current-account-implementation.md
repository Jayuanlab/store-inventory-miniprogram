# 供应商模块实施说明

更新：2026-09-07。这里说明当前实际可用的功能；完整目标模型见 `supplier-current-account-model.md`。

## 使用入口

老板登录后在“首页 → 供应商往来”进入；“收支账款”也保留同一入口。

供应商列表分别显示我待付、对方应退、预付余额、仅抵货款额度。点击供应商后可查看待结款项、往来明细、进退货和对账单；四类余额不自动净额抵销。

## 已实现流程

1. 建档：供应商使用稳定 ID；名称重名需要区分实际主体。已有旧采购按原名称生成带核对标记的档案，不伪造现金记录。
2. 期初：老板填写截至期初的四类余额及核对依据；已有往来时禁止叠加期初，避免重复账款。
3. 订货：记录约定商品、数量、价格，可同时记录真实预付款；没有到货不增加可售库存。进货页顶部“待收货”显示未收完的订货单，分别列订货、已收、待收数量。
4. 收货：独立入库或点击待收货单的“到货入库”，带出供应商、商品、约定单价及剩余数量，再确认实际数量和串码。订货收货不再选择付款方式，自动抵用明确关联本单的可用预付款，余额不足形成待付；老板和店长查看只读的预计抵用、待付和剩余预付款。分批入库更新待收数量，并产生“最近入库”记录；全部收完或已终止的单据不再列入待收货。
5. 付款：默认未付。老板可以登记本次付款、勾选多张货款分配，付款不够则部分结清，多付保留预付款。
6. 抵款：选择一笔可用款项和一笔待付货款，确认后两端余额同步减少；没有现金流水。
7. 退款：从已确认应退或预付款余额中登记实际到账；仅抵货款额度不允许冒充现金退款。
8. 纠正分配：可撤销本版本生成的抵扣或付款核销，原现金记录保留、款项恢复未分配；真实退款必须另行登记。
9. 采购退货：按原采购明细选择实际退回数量/串码，填写供应商认可的退款单价和确认编号，先预览成本与款项，再确认出库。退货款可退款或抵账，不自动当成已收到现金。
10. 调价：按已确认协议选择当前在库、本批全部含已售或指定串码，填写本次每件补差/追加金额、确认编号、依据及结算性质。先预览影响，再确认；预览后数据变化会要求重新计算。
11. 对账：选择期间，查看分类期初期末、往来明细、真实收付，并导出含三个工作表的 Excel。

“往来更正”用于有明确核对依据的余额补记，不代替商品调价，不伪造现金流水。减少原待付可通过确认对方应退后抵扣，必须保留业务依据。真实费用报销、服务费收入等尚未自动映射正式财务费用或收入科目。

### 订货收货与付款分离

- 订货时的实际预付款保存明确的订货关联。后来付款可在供应商“付款”中选择“关联订货预付”；补已入库货款则勾选待结款项，二者不混用。
- 收货按实际入库金额先抵本单可用预付款，不新增现金流水。多预付的钱仍留作预付，不自动退钱；少预付或未预付也可入库，尾款在供应商往来单独登记。
- 自动抵用只处理本订货单的付款余额，不自动使用其他订货单、未指定订货的预付款、价保款或仅抵额度。已退款、已被抵用的金额不会重复使用。
- 余额或收货进度在页面打开后发生变化，会要求刷新后确认；入库和抵用在同一事务提交，相同请求重试只处理一次。
- 仓管可确认收货，由系统执行已确定归属的预付款抵用；不返回预付款金额，也不能新增实际付款或选择其他抵款来源。
- 旧记录仅在原版本保存的完整订货编号、创建人及时间、付款与账款双向引用、主体和金额全部匹配且唯一时补关联；不修改原金额或已有结算，不根据供应商名称或金额相同猜测关联。

## 成本与报表

串码商品沿原进货串码追溯在库或销售去向，调整后保留原采购和销售快照，追加成本调整明细。客户退回已补差商品时，以调整后的对应成本恢复库存，避免重新销售仍用旧进价。

普通商品自本版本起保存移动平均成本来源份额。进货建立份额，出库按占比分摊，客户实物退货恢复对应份额；维修耗材沿所属销售单追溯。整批补差可分配到当前库存和已经销售/耗用的成本，不修改原销售单及提成快照。

这些份额不是实物批次。混合供应商的普通库存不能自动判断“哪家供应商的实物还剩多少”，因此只有全部当前库存可明确归属所选进货来源时才允许自动做当前库存价保。历史来源缺失、盘点变化、采购退货等导致进货数量不能完整追溯时，整批自动分配也会明确拒绝。

每日经营分别列原销售毛利、当日确认的已售成本调整影响、含调整毛利和采购退货价差。调整剩余库存的价值不全部计入当天利润。供应商实付和实退按用户填写的实际收付日期汇总；往来确认及核销按登记日，期初按指定期初日。

后续补差暂不补发或扣减工资，已确认工资保持原样。这不是将“永不补发”设为经营政策，而是在用户确认前不自动变更员工工资。

## 权限

| 动作 | 老板 | 店长默认 | 仓管默认 | 店员默认 |
| --- | --- | --- | --- | --- |
| 供应商基本资料、订货与收货 | 可以 | 可以 | 有采购权限时可以 | 不可以 |
| 查看供应商全部往来 | 可以 | 可以 | 不可以 | 不可以 |
| 付款、退款、抵扣及撤销核销 | 可以 | 需独立授权 | 不可以 | 不可以 |
| 调价、采购退货与往来更正 | 可以 | 需独立授权 | 不可以 | 不可以 |
| 期初确认 | 可以 | 不可以 | 不可以 | 不可以 |

服务端权限代码为 `supplier:view`、`supplier:settle`、`supplier:adjust`。当前没有新增授权管理页面；角色默认如上，不能把“能设置工资规则”推断为“能确认供应商资金”。

仓管可看进货事实与实际进价，但采购列表接口不返回已付、未结、核销余额。调价及采购退货当前是金额和实物已经核对完的一次确认，由老板办理；仓管先填待退货物流单、老板再确认退货款的分阶段界面尚未实现。

## 数据与安全

- 金额以整数分保存在往来项和核销记录中；核销不超过来源可用额或目标未结额，不跨供应商主体。
- 写接口沿用登录会话、服务端鉴权、幂等请求编号和 SQLite 事务；价格预览与确认使用结果指纹，防止用旧预览提交。
- 旧采购与付款快照保留，旧 `paidAmount` 不再是余额计算依据；余额来自往来项和有效核销。
- 不重新导入商品库存，不添加真实供应商欠款，不替用户假定工资。期初往来需要逐家核对，与库存期初独立。
- 确认编号在同供应商调整记录内防重复；每个编号当前对应一条商品调整明细，多商品协议需使用“协议号-明细号”区分。
- 对账单未实现银行自动勾兑或供应商线上确认；所有记录由内部人员依据实际业务登记。

## 本轮未实现

借机寄售、供应商保修换机、保证金、老板个人代付独立账户、复杂条件返利、供应商兼客户的跨业务抵账、正式财务税费核算不在本阶段。不能通过普通采购/费用记录冒充这些流程。

调价申请审批、附件上传、指定历史截止日的自动资格快照、补差自动撤回及其对历史退货/工资的全链条补调也尚未实现。当前调价适用范围明确为当前库存、整批、人工核对后的指定串码。不同品类、有效期等复杂抵扣限制没有独立配置页面。

## 验证

`npm run server:test` 验证往来余额、串码和加权成本、退货、工资不改写、权限、并发与幂等；`npm run suppliers:test` 在独立内存 HTTP 服务上驱动实际页面方法，走通建档、期初、预付、采购、补差、抵扣、部分付款、退款、退货和 Excel 导出。

`npm run wechat:check` 使用微信编译器检查全部页面。`npm run suppliers:qa` 在本机微信模拟器验证布局和截图；有金额的验收样本只覆盖页面内存，显示为“隔离账套”，不提交任何真实采购、付款或退款，退出时回到真实首页。
