# 手机店内部进销存业务模型

这份模型面向手机店内部管理，不包含顾客商城、购物车、线上下单和营销活动。系统的核心目标是让老板知道：货从哪里来、现在在哪里、被谁卖掉、收了多少钱、赚了多少、有没有异常。

## 一、业务边界

当前系统包含：

- 资料管理：商品、SKU、供应商、客户、员工、角色权限。
- 进货管理：采购入库、采购退货、进货查询。
- 销售管理：销售开单、销售退货、销售查询。手机、号卡、配件、维修收费都通过销售单确认收入。
- 库存管理：库存查询、串码跟踪、盘点、报损、库存预警。
- 维修管理：维修接机、维修派工、维修报价、维修完成。维修销售收入和毛利归入销售模型。
- 财务管理：收款、付款、应收款、应付款、费用支出。
- 报表管理：销售报表、毛利报表、库存报表、员工业绩。

当前系统不包含：

- 顾客端商城。
- 顾客自助下单。
- 线上支付闭环。
- 分销、优惠券、会员积分。

## 二、核心参与者

### 老板

老板拥有最高权限，重点关注经营结果和风险。

老板需要看到：

- 今日销售额。
- 今日毛利。
- 库存成本。
- 员工业绩。
- 应收应付。
- 库存预警。
- 操作日志。

老板可以操作：

- 管理员工和权限。
- 修改商品成本和售价。
- 作废单据。
- 做盘点调整。
- 查看全部财务和利润数据。

### 店长

店长负责日常经营管理，可以处理多数业务，但不一定能看到全部利润。

店长可以操作：

- 商品资料维护。
- 采购入库。
- 销售退货。
- 库存盘点。
- 查看门店经营数据。

### 员工

员工负责销售、维修接机和库存查询。

员工可以操作：

- 销售开单。
- 查询库存。
- 查询自己的销售记录。
- 录入客户信息。
- 接维修机。
- 处理自己有技能完成的维修项目，并通过销售单收取维修费用。

员工默认不能操作：

- 查看总利润。
- 查看成本价。
- 删除或作废单据。
- 修改库存。
- 管理其他员工。

### 仓库员

仓库员负责商品入库、出库复核、库存盘点、串码核对和报损登记。

仓库员可以操作：

- 查询库存。
- 采购入库复核。
- 扫描或录入 IMEI、ICCID。
- 库存盘点。
- 报损登记。
- 门店调拨出入库。
- 维修接机入库和维修机保管。

仓库员默认不能操作：

- 查看销售利润。
- 修改商品售价。
- 作废销售单。
- 管理员工权限。
- 查看完整财务报表。

## 三、商品模型

手机店商品按两层分类：业务品类和商品细类。业务品类用于开单和报表，商品细类用于搜索和库存分析。

| 业务品类 | 示例 | 第一阶段库存方式 | 关键字段 |
| --- | --- | --- | --- |
| 手机 | IQOO NEO11 16+512、OPPO A6T 6+256 | 先按数量管理，后续补 IMEI | 品牌、型号、内存、颜色、版本、成色 |
| 号卡 | 100元号卡、巴渝卡59元档 | 先按数量管理，后续补 ICCID/手机号 | 运营商、套餐、档位、激活状态 |
| 零配件 | 充电器、数据线、摄像头、路由器、耳机、手机膜 | 普通库存 | 商品细类、规格、型号、数量 |
| 维修 | 换屏、换电池、主板检测 | 服务商品，不管理库存 | 维修项目、维修成本、外修成本、维修人员 |

真实库存表目前没有商品大类字段，需要系统导入时根据商品名称初步识别业务品类和商品细类，并允许人工修正。维修项目是可销售的服务商品；客户付款时通过销售单确认收入和毛利。

零配件建议增加商品细类：

```text
充电器
数据线
充电宝
摄像头
路由器
耳机
贴膜
保护配件
电池类
其他配件
```

### 商品与 SKU

商品用于表达一类可销售对象，SKU 用于表达可开单、可定价、可计算成本的具体规格。真实库存导入后，管家婆的商品编号应保存为外部商品编号，用于后续对账。

示例：

```text
商品：iPhone 15
SKU：iPhone 15 / 128G / 黑色 / 国行
库存实体：IMEI 356789100023451
```

第一阶段如果没有 IMEI 明细，也可以先这样：

```text
商品：OPPO A6T 6+256
SKU：OPPO A6T 6+256
库存余额：3 台
```

号卡示例：

```text
商品：移动号卡
SKU：移动 29 元套餐卡
库存实体：ICCID 898600221900001
```

第一阶段如果没有 ICCID 明细，也可以先这样：

```text
商品：巴渝卡59元档
SKU：巴渝卡59元档140元
库存余额：18 张
```

零配件示例：

```text
商品：Type-C 数据线
SKU：Type-C 快充数据线 / 1 米 / 白色
库存余额：42 条
```

维修项目示例：

```text
商品：维修服务
SKU：iPhone 换屏 / 国产屏
成本来源：屏幕总成成本 + 外修成本
销售明细：维修收费 380 元，成本 185 元
```

## 四、库存模型

库存必须由两层组成：

- 库存余额：当前某个 SKU 还剩多少。
- 库存流水：每一次为什么增加或减少。

不要只保存库存数量。所有库存变化必须生成库存流水。

### 库存变化来源

| 业务动作 | 库存影响 | 是否生成流水 |
| --- | --- | --- |
| 采购入库 | 增加库存 | 是 |
| 采购退货 | 减少库存 | 是 |
| 销售出库 | 减少库存 | 是 |
| 销售退货 | 增加库存或转入待检 | 是 |
| 报损 | 减少库存 | 是 |
| 盘点调整 | 增加或减少库存 | 是 |
| 门店调拨 | 一个门店减少，另一个门店增加 | 是 |

### 串码库存状态

手机和号卡都应该作为库存实体追踪状态。

通用状态：

```text
可售
已预留
已售
退货待检
已退供应商
已报损
```

号卡可扩展状态：

```text
未激活
已售未激活
已激活
激活失败
已注销
```

手机可扩展状态：

```text
新机可售
二手机可售
售后中
维修中
退货待检
```

### 串码规则

- 同一个门店内，IMEI 或 ICCID 不能重复入库。
- 已启用串码管理的商品销售时必须选择具体串码。第一阶段真实库存没有 IMEI/ICCID 明细时，手机和号卡可以先按数量管理。
- 已售、已报损、已退供应商的串码不能再次销售。
- 销售退货时，串码不能直接恢复可售，建议先进入“退货待检”。
- 盘点时，串码商品以具体库存实体为准，普通商品以数量为准。

## 五、单据模型

单据是业务事实的载体。库存和财务不应该脱离单据单独变化。

### 采购单

采购单记录从供应商进货。

关键字段：

- 单据编号。
- 供应商。
- 经办人。
- 商品明细。
- 数量。
- 成本价。
- 串码列表。
- 应付金额。
- 已付金额。
- 单据状态。
- 创建时间。

采购单状态：

```text
草稿
已入库
已部分退货
已全部退货
已作废
```

### 销售单

销售单记录门店卖出的商品或服务。维修收费也属于销售单。

关键字段：

- 单据编号。
- 客户。
- 经办员工。
- 商品明细或服务明细。
- 数量。
- 售价。
- 成本价快照。
- 串码。只有已启用串码管理的商品必须填写。
- 应收金额。
- 实收金额。
- 收款方式。
- 毛利。
- 单据状态。
- 创建时间。

销售单状态：

```text
草稿
已完成
已部分退货
已全部退货
已作废
```

### 退货单

退货必须关联原始单据。

销售退货规则：

- 必须选择原销售单。
- 不允许退超过原销售数量。
- 已启用串码管理的商品必须退回原串码。
- 手机退货默认进入退货待检。
- 退货需要冲减销售额和毛利。

采购退货规则：

- 必须选择原采购单或供应商。
- 已启用串码管理的商品必须选择具体串码。
- 已售商品不能采购退货。
- 采购退货会减少库存并减少应付款。

## 六、财务模型

财务模型先做经营账，不做完整会计系统。

### 收款

销售单产生应收金额，实收金额进入收款账户。

收款方式：

```text
微信收款
支付宝
现金
银行卡
组合收款
赊账
```

如果实收金额小于应收金额，差额形成客户应收款。

### 付款

采购单产生应付金额，已付金额从账户扣减。

如果已付金额小于应付金额，差额形成供应商应付款。

### 费用

费用是非销售项目成本支出，例如房租、水电、快递、人工补贴。

费用影响老板看到的净经营结果，但不改变商品毛利。

### 利润

第一阶段至少区分：

```text
毛利 = 销售金额 - 商品成本
经营净额 = 毛利 - 费用
```

成本价必须在销售单生成时做快照。后续修改商品或维修项目成本价，不能影响历史销售毛利。

## 七、权限模型

权限应按动作设计，而不是只判断角色名称。

基础权限：

```text
product:view
product:create
product:update
cost:view
sale:create
sale:return
sale:void
purchase:create
purchase:return
stock:view
stock:adjust
finance:view
finance:view_profit
employee:manage
report:view
operation_log:view
```

角色默认权限：

| 角色 | 权限特点 |
| --- | --- |
| 老板 | 全部权限 |
| 店长 | 大多数业务权限，可限制成本和利润 |
| 员工 | 销售开单、库存查询、查看本人业绩 |
| 仓库员 | 入库复核、串码核对、盘点、报损、调拨，不看利润 |

## 八、核心业务流程

### 采购入库

```text
选择供应商
-> 选择商品/SKU
-> 填数量和成本价
-> 手机/号卡录入串码
-> 确认入库
-> 生成采购单
-> 增加库存余额
-> 新增库存实体
-> 写库存流水
-> 生成应付款或付款记录
-> 写操作日志
```

### 销售出库

```text
选择客户或散客
-> 选择商品/SKU
-> 手机/号卡选择具体串码
-> 填售价和收款方式
-> 确认销售
-> 生成销售单
-> 扣减库存余额
-> 更新串码状态为已售
-> 写库存流水
-> 生成收款记录或应收款
-> 计算毛利
-> 写操作日志
```

### 销售退货

```text
选择原销售单
-> 选择退货明细
-> 普通商品按数量退回
-> 串码商品按原串码退回
-> 手机/号卡进入退货待检
-> 生成退货单
-> 调整库存
-> 冲减销售额和毛利
-> 写库存流水
-> 写操作日志
```

### 盘点调整

```text
选择盘点范围
-> 录入实盘数量或扫描串码
-> 系统计算盘盈盘亏
-> 老板或店长确认
-> 更新库存
-> 写库存流水
-> 写操作日志
```

## 九、关键约束

- 商品可以改名和改售价，但历史单据必须保留当时的名称、售价和成本价快照。
- 库存余额不能手工直接修改，必须通过单据或盘点调整。
- 销售出库时必须校验库存是否足够。
- 串码商品必须校验串码是否可售。
- 作废单据必须保留原单和操作日志，不能物理删除。
- 老板查看利润，员工默认不显示成本和毛利。
- 财务账户流水和库存流水都必须能追溯到来源单据。

## 十、建议的聚合边界

后续写代码时，可以按以下业务聚合拆分：

- 商品资料：商品、SKU、分类、品牌、定价。
- 库存：库存余额、库存实体、库存流水、盘点、报损、调拨。
- 采购：采购单、采购明细、采购退货、供应商应付。
- 销售：销售单、销售明细、销售退货、客户应收。维修收费作为销售明细。
- 财务：收款、付款、账户、费用、应收应付。
- 权限：用户、角色、权限、操作日志。
- 报表：销售统计、毛利统计、库存统计、员工业绩。

其中库存是最核心的共享能力。采购、销售、退货、盘点都应该调用库存能力，而不是各自直接修改库存。

## 十一、维修业务模型

维修业务不再和商品销售分开确认收入。维修接机是过程管理，最终收费进入销售单。

维修接机记录关键字段：

- 接机编号。
- 客户姓名和手机号。
- 机器型号。
- IMEI。
- 故障描述。
- 接机人。
- 维修人员。
- 维修状态。
- 报价金额。
- 预计维修成本。
- 关联销售单号。
- 创建时间。

维修状态：

```text
待检测
待报价
待维修
维修中
待取机
已取机
无法维修
```

维修收费开单：

```text
销售单明细 = 维修项目
维修项目毛利 = 维修收费 - 维修配件成本 - 外修成本
```

关键规则：

- 维修接机记录不单独确认收入。
- 维修收费必须生成销售单，算一次销售。
- 维修项目不扣手机库存。
- 维修配件可以有独立库存，消耗时减少维修配件库存。
- 维修项目毛利计入销售毛利。
- 店员可以有不同维修技能，维修单应该能分配给具备对应技能的人。
